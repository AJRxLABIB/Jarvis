# Round 64: finishing round 63 and the remaining gaps

Unit-tested with fakes and temporary databases (`tests/test_round64.py`, 23 tests). **Not run on your real PC / phone. The Qt pages are not exercised by automated tests.**

* **Git readers** (`core/gitinfo.py`): `git log --since` + `git status` (read-only, through the reviewed command executor) feed the event diagnosis: "changed before it: app.py, config.json (uncommitted)", plus how often the same event happened before. No git / not a repo = the diagnosis says that evidence is missing. `BuildFailed` now carries the project folder.
* **Meeting detector** (`core/meeting.py`): meeting app (Zoom, Teams, Webex, Skype, Slack, Discord, Meet in a browser tab) in front AND the microphone in use by it = meeting. Microphone alone is not a meeting; Jarvis's own listening is ignored; unknown microphone state gives at most a "low confidence" meeting. Feeds `attention.may_speak`. Windows readers (foreground program, microphone consent registry) are unverified on hardware.
* **Phone-verified transactions** (`transactions.reconcile`, `transaction_tool.find_command`): a running phone step is settled from the phone's own `phone_commands` row for that device and action sent after the step began: `done` verifies it (the phone's result is the evidence), `failed / unsupported / expired / cancelled` fails it. The background upkeep loop and `status / next / options / reconcile` do this automatically. Sending the command still goes through the normal phone-link approval; the transaction tool never sends one. Limit: if you send the same action twice, the newest one counts.
* **Guardian attribution** (`guardian.read_holders`): when a burst is reported, which programs have files open in the watched folders right now. It is direct evidence but only a moment in time; Windows hides some processes. Combined with the existing disk-write suspects (a labelled guess).
* **Retention** (`core/retention.py`, tool `retention`): one view of what is kept (notifications, event log, clipboard memory, health readings, recorded activity, finished tasks, closed incidents), for how long, and `clear` for ONE store, with a confirmation and the note that backups and logs are separate copies.
* **App profiles** (`core/app_profiles.py`): `press_control` tries the app's other labels for what you asked ("Save" -> "Save As" in Notepad), and when nothing matches adds the app's shortcut (offered as text, never pressed silently) and why the app hides its controls (Electron / browsers). Dialog texts where a wrong press loses work are marked for "always ask".
* **VS Code and Office adapters** (`tools/editor_tools.py`, `core/office_info.py`): `vscode` (open at a line, folder, diff, extensions; fixed argument lists, checked paths) and `office_info` (Word headings / words, Excel sheets and formulas, PowerPoint slide titles, no Office needed, macro files refused, zip-bomb limits).
* **Panels**: Coordination, Guardian, Skills, Data kept (`ui/command_center/panel_specs.py` + `tool_panel.py`). Each block / button is an existing tool run as your own command, so permissions, confirmations and audit are the same as in chat. A test checks that every block and action names a real tool with valid arguments.
* **Phone**: new read-only command `overview` (situations, security, cross-device tasks, what changed) in the signed mobile protocol (read permission). The Android screen that shows it is NOT built (no JDK here).

Still not built: Android UI for `overview` and NSD discovery, a visual (drag and drop) Skill Studio editor beyond the existing Workflow Studio, per-file audit of who changed a file (needs Windows auditing), Office editing beyond the existing tools, real-device validation of all of this.
