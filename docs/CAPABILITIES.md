# What works where

Generated by `python run.py --capabilities` from the tools that are really registered.

## Features

| Feature | Works | Needs |
|---|---|---|
| Privacy zones: password managers, banking, private browsing and meetings (and zones you add) make Jarvis stop capturing the screen, remembering the conversation, saving the clipboard, indexing and letting a phone view or control the screen while they are in front | offline | decided from the foreground program and window title (Windows reader unverified on hardware); a zone only restricts, and switching one off asks first |
| Guardian also notices new removable (USB) drives and changes to watched files (content hash; only hashes are stored) | offline | drive identity is letter + size + volume serial where Windows gives it; cannot say who changed a file; Windows readers unverified |
| Self-learning loop upgrades: failure reflection (a failed tool call that worked next time with other arguments becomes a lesson), faded items rank lower, corrected mistakes lead the self-test, weekly learning audit (reports, never retires on its own), privacy-zone block on history indexing | offline | rule-based; unverified on long real use |
| Physical sensors over a local MQTT broker (ESP32 / ESPHome / Zigbee2MQTT): temperature, humidity, door, motion; readings that are old or missing are reported as unknown, impossible values as invalid | local network | read-only, anonymous private-network broker; tested with a fake broker, not real sensors |
| Plugin capability scan: shows what a plugin file does (network, processes, native code, dynamic execution) before you trust it | offline | static review aid, not a sandbox |
| Local read-only MCP server: programs on this PC (Claude Desktop, IDE agents) can call a short whitelist of SAFE status tools; 127.0.0.1 only, bearer token (stored hashed), Host / Origin checks, rate limit, audited | offline | off by default (MCP_SERVER_ENABLED); never serves anything above SAFE; tested with local clients only |
| Sensor rules and twin: notify-only rules on fresh sensor readings (door open too long, room too hot), sensors in the digital twin and radar warnings; plugins are probed in a restricted child process before they can be trusted | local network | notify only, never switches anything; import-time containment, not a full sandbox; not verified with real sensors |
| Resource orchestration for a small GPU: NVML / nvidia-smi readings, will-it-fit with a VRAM safety margin using memory measured when a model was loaded, loaded-model book, idle-unload rule, P0-P4 workload scheduler (not yet wired into every AI path); every tool result carries a verification state and one tool lists which actions cannot be double-checked | offline | pure logic tested with fake readers; real GPU behaviour unverified; scheduler is a library until wired in |
| Problem investigation: from a symptom, collects evidence (logs, resources, checks, events) and ranks causes as CONFIRMED / STRONGLY_SUPPORTED / POSSIBLE / UNKNOWN with safe next steps and a recheck after a fix; deadline risk across todos and goals with the rule behind each line | offline | rule table, no AI call; repairs still need your approval; unverified on long real use |
| Learning quality control: finds learned skills / lessons that hurt, contradict a better one or faded; reversible cleanup with a ledger; corrected mistakes kept as hard test cases | offline | rule-based (no AI call); only flips the retired flag, request history untouched; unverified on long real use |
| Adaptive interaction advice: which of voice, keyboard, gestures or phone fits now (meeting, full-screen app, quiet / sleep mode) and whether replies should be spoken | offline | advice only; it never switches anything by itself |
| Meeting-aware interruptions: non-urgent notices wait while a meeting app is in front and the microphone is in use by it (the microphone alone is not a meeting) | offline | Windows only; reads the foreground program and the microphone consent store; unverified on hardware |
| Event diagnosis with git: what changed in the project before a crash (read-only git log / status) and how often it happened before | offline | needs git and a project folder; otherwise the diagnosis says that evidence is unavailable |
| Cross-device tasks settle themselves from the phone's own command results (no id to pass); a failed or unsupported command fails the step instead of faking success | offline | needs a paired phone and the phone-link command for the step to be sent through its normal approval |
| Guardian shows which programs have files open in the watched folders when a burst is seen (direct, but only a moment-in-time view) | offline | Windows may hide protected processes; not a per-file audit log |
| VS Code control (open at a line, folder, diff, extensions) and Office file summaries (Word / Excel / PowerPoint structure) without Office installed | offline | needs the 'code' command on PATH; macro files are refused |
| Data kept: see what is stored, for how long, and clear one store (with the honest note that backups and logs are separate copies) | offline | clearing asks first |
| App-aware desktop control: per-program labels, shortcuts and notes (Notepad, Explorer, Word, Excel, PowerPoint, Outlook, browsers, VS Code, chat apps) used when a named control is not found | offline | profiles are standard defaults; poor-accessibility apps (Electron, browsers) still expose few controls |
| Command-center pages: Coordination, Guardian, Skills, Data kept; the phone can ask for a read-only 'overview' | offline | Qt pages are not tested by automated tests; the Android screen for 'overview' is not built |
| Cross-device transactions: one task across the PC and a phone with an owner device per step, dependencies, checkpoints, completion only when every step is verified by its own device (a phone step needs a result the phone returned), and recovery choices when a device drops | offline | bookkeeping only: the steps are run by the normal tools; needs a paired phone for phone steps |
| Event intelligence: related events (a crashed project, what changed before it, earlier similar events) become one explained situation with next steps and a stated confidence | offline | only as good as the events and logs captured; git / history readers are optional |
| Attention firewall and mode scheduling: non-urgent notices wait while a full-screen app, a meeting or a focus block is active; gaming / presentation / power saving / meeting / offline / quiet modes change which background work runs | offline | full-screen detection is Windows-only and unverified on hardware; urgent security notices are never delayed |
| What changed while you were away: events, notifications, missions, files in watched folders (names only), devices and security incidents since a time you give | offline | file scan is bounded; sources that cannot be read are listed, not skipped silently |
| Dependency-aware health: when one part fails (AI engine, database, disk) say what still works, what is limited and what is unavailable | offline | static dependency table; repairs still need your approval |
| Verified project start: start the project's usual command with no window, wait, then say whether it is really running (its port answers) or crashed, with the cause read from its log (missing package, port in use, syntax error, ...) and the next step; also status, log tail and stop | offline | needs the project's own tools installed; Windows; logs are untrusted text |
