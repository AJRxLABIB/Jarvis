# Feature-by-feature gap map (27 Oct 2026, from the repository)

Evidence = code and tests that were read or grepped in this repository; nothing here was run on real Windows, a phone, a
microphone or the GPU, so no row is "validated on hardware". Statuses: IMPL+TESTED, INCOMPLETE, NOT INTEGRATED, HARDWARE-UNVERIFIED,
MISSING, NOT FEASIBLE.

| # | Feature | What already exists (reused) | Status | Genuinely missing | Priority |
|---|---|---|---|---|---|
| B | Time-travel task debugger | `agent_runs` + `audit_log.run_id` (`app/core/runs.py`), `explain.py` (words about safety decisions per run), `timeline.py` (activity list), missions + step states, `retry.should_retry`, `capability_gaps.classify`, Reliability Lab | **INCOMPLETE** (runs can be explained in prose) | structured per-call timeline with arguments/durations/verification, recorded-vs-reconstructed labelling, missing-data detection, earliest divergence, recovery plan that respects repeatability, trace / simulation / live replay with a repeatability gate, sensitive-tool exclusions | **1 - built this round** |
| A | Tool and workflow foundry | `evolution/*` + tools `propose_code_change`, `test_proposal` (copy of source, full suite + lint), `apply_proposal` (backup), `rollback_proposal`; `capability_gaps` classifies "missing tool" and proposes text | **INCOMPLETE** | nothing generates a *new tool* from a request: no scaffold with declared inputs/outputs/permissions, no isolated run against mocks, no registry hook for approved generated tools. The proposal/test/apply/rollback pipeline already covers the safe-change part | 2 |
| C | Contextual workspace intelligence | saved window layouts (`tools/layouts.py`: apps + positions, restore starts missing apps), `context_engine.py` (active window, project, recent), projects (`core/projects.py`), missions `unfinished()` | **INCOMPLETE** | a workspace object that joins project + folder + files + goal + unfinished mission + restore instructions; preview of what would open; missing-file/app report; per-signal disable; rejection that doesn't become a preference | 3 |
| D | Unified personal retrieval | `unified_search.py` (memories + documents + history ranking), `semantic_items` table with embeddings + mtime, document indexing tools, `memory2.py` contradictions, `synthesis.py` briefs with staleness/conflicts | **IMPLEMENTED BUT INCOMPLETE** | source adapters for repositories / calendar / note exports, source include-exclude controls, near-duplicate detection, hybrid lexical+semantic fusion verified by a test | 4 |

Ranking rationale: B has the most reusable infrastructure (every run is already audited), the clearest user benefit (a failed
task becomes understandable and reproducible), the lowest privacy risk (reads data already kept) and is fully testable here. A needs
a code-generation model to be useful and its dangerous part (applying code) is already built. C/D/G follow once B's data exists.
